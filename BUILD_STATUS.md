# Build status — 22 October 2026

## Evidence-authenticity remediation (latest)

A second security audit found the remaining critical gap: a claimant could still obtain NOT_AFFECTED/REMEDIATED clearance purely from their own convincing appeal/remedy text plus a made-up hash, because `resolve_appeal`/`resolve_remedy` evaluated that text directly. Fixed by adding a mandatory, independent **evidence attestor** layer: an admin-managed issuer registry (`authorize_issuer`/`revoke_issuer`), a case-bound `Attestation` record whose identity fields (product, serial, notice, notice digest, product revision, assessment generation) are captured by the contract itself — never issuer-supplied — and a hard precondition that `resolve_appeal`/`resolve_remedy` will not even run the classifier without a current, matching, non-consumed attestation from a non-owner issuer. The claimant's own evidence text is no longer read by the clearance evaluator at all. Redeployed and reproduced live, with an explicit honesty caveat: a GenLayer test wallet stood in for the issuer, which demonstrates the mechanism, **not** real manufacturer/repair-provider identity. **Current contract:** `0x3b8E072EF980725C30c974438C8a1928080baaf8`, deploy tx `0xb0edf6dc4dde432cbdc2b9ad03797f57b69022742da475278f2d74ee7c626f0f`, FINALIZED. **Current `ReleaseGuard`:** `0xd53470c49c25BCB545b2df4acbC6F25C0Ef027dC`. Full writeup with every revert payload and transaction hash in [`docs/LIVE_PROOFS.md`](docs/LIVE_PROOFS.md) section F.

## Not completed / must not be claimed

- **Source verification is re-fetch-and-compare consensus, not cryptographic proof of government authorship.** `verify_source_notice` independently fetches the claimed URL and reaches leader+validator agreement that the claim matches it, binding a sha256 digest — demonstrated live against a real CPSC recall (see `docs/LIVE_PROOFS.md` section B). Trust in the domain itself still rests on a hardcoded allowlist (`AUTHORIZED_SOURCE_PREFIXES`), not an on-chain governance or signature mechanism, and GenVM's own HTTP fetch is trusted for TLS/domain integrity rather than independently re-verified by the contract.
- **No staking/governance for the filer allowlist** (handoff item 3, partially addressed) — authorization is gated by a single admin address, not a stake-weighted or multisig/governance process; a compromised admin could authorize an unreliable filer. A notice that fails verification still cannot gate a product, which limits but does not eliminate the griefing surface.
- **Appeal/remedy evidence_hash is an auditable commitment, not a verified artifact.** The audit fix (section E5) requires unit-bound text and a mandatory hash, but the contract never fetches or checks what that hash points to -- note this field is now purely an audit trail and is never read by the clearance evaluator at all (see the evidence-authenticity remediation above).
- **Issuer identity is unproven.** `authorize_issuer` grants an on-chain privilege; it is not KYC and cannot prove the authorized address is a real manufacturer or repair provider. This session's live demonstration explicitly used a GenLayer test wallet and says so plainly in `docs/LIVE_PROOFS.md` section F.
- A few early transaction hashes from the first deployment's lifecycle run were not retained in captured CLI output (truncated before the hash line) and the public GenLayer explorer was returning `503 DEPLOYMENT_PAUSED` when I tried to recover them afterward; every such step is still backed by an on-chain state read, documented in `docs/LIVE_PROOFS.md`, rather than an unverifiable claim. All second-deployment hashes were captured directly.
- Stress tests and replay/race tests were not performed this session.
- Real auditor identity, production manufacturer authenticity, and full legal regulatory compliance remain out of scope, as before.
